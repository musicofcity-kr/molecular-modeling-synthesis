# N1 Learning Experience

## 경험 목표

고등학생이 실물 분자모형을 촬영한 뒤 인식 결과를 직접 확인·수정하고, 확정한 연결 구조와 별도로 제공되는 Scientific Reference를 탐색하여 두 구조의 차이를 자신의 말로 설명한다.

교사의 의도는 학생에게 정답 모형을 즉시 보여 주는 것이 아니라 다음 학습 순환을 완성하게 하는 것이다.

`직접 제작 → 관찰 → 확인·수정 → 화학 검증 → Reference 탐색 → 비교 → 설명 수정`

## 경험 구조 결정

- **6단계, 한 화면 한 핵심 행동**으로 진행한다.
- Scanner는 기존 대형 `App.tsx`에 섞지 않는 **feature-owned state와 lazy shell을 가진 독립 학생 흐름**으로 설계한다. 안정된 Ketcher adapter, RDKit gate, 3D viewer만 경계 뒤에서 재사용한다. N2는 현재 simple 기본 진입과 `legacy` 의미를 바꾸지 않는 opt-in 진입을 추가해야 하며, 정확한 URL/query 형식만 N2에서 결정한다.
- 모바일에서는 한 번에 한 구조를 크게 보여 주고 명확한 전환 버튼을 사용한다. 데스크톱 비교 단계에서만 두 구조를 나란히 보여 준다.
- 단계 상단에는 `현재 단계 / 6`, 단계 이름, 완료 상태를 표시한다. 이전 단계로 돌아갈 수 있지만 원자·결합을 변경하면 이후 검증·정체·3D·측정 결과를 지운다고 먼저 알린다.
- 각 화면의 주 행동은 하나만 강조한다. hover 전용 도움말, 개발자 용어, AI 채팅창은 사용하지 않는다.
- 첫 화면 30초 안에 촬영/불러오기 행동을 찾고, 사진 입력 후 3분 안에 첫 원자 후보를 확인하며, 5분 안에 전체 여섯 단계의 목적을 설명할 수 있게 한다.

## 전체 학생 흐름

```text
1. 사진 준비
   ↓
2. 원자 확인
   ↓
3. 결합 확인
   ↓
4. 구조 검증·분자 확인
   ↓
5. Scientific Reference 3D 탐색
   ↓
6. Physical Model과 비교·설명 수정
```

## 1단계 — 내가 만든 모형 사진 준비

### 학생이 보는 것

- 제목: `1/6 내가 만든 모형 촬영`
- `내가 만든 모형 · Physical Model` 출처 배지
- 촬영, 사진 불러오기, 짧은 촬영 가이드
- 안내: `사진은 원자와 연결 관계를 찾는 데 사용합니다. 사진 속 거리나 막대 길이를 실제 결합길이로 계산하지 않습니다.`

### 학생 행동과 생각

- 분자모형 하나가 잘 보이도록 촬영하거나 기존 사진을 고른다.
- 흐림, 강한 그림자, 가려진 원자, 화면 밖으로 잘린 부분이 없는지 미리보기를 확인한다.
- 생각할 질문: `모든 원자와 연결 막대가 한 사진에 보이는가?`

### 수정 지점과 오류 후 행동

- `다시 촬영`, `다른 사진 선택`, `사진 삭제`를 언제든 사용할 수 있다.
- 사진 품질이 낮으면 이유를 한 문장으로 알려 주고 재촬영을 우선 제안한다.
- 분석이 시작되지 않거나 실패해도 `원자를 직접 표시하기`로 2단계에 진입할 수 있다.
- H/C/N/O/F/Cl 이외의 원자로 보이면 지원 범위를 알리고 지원 활동을 선택하거나 교사에게 확인하도록 한다. 임의 원소로 바꾸지 않는다.

### 완료 신호

- 학생이 미리보기를 보고 `이 사진으로 원자 찾기`를 선택한다.

## 2단계 — 원자 후보 확인

### 학생이 보는 것

- 제목: `2/6 원자 확인`
- Physical Model 사진 위 원자 중심 표시와 원소 기호
- 요약: `원자 5개를 찾았습니다 · 확인 필요 1개`
- 후보 상태는 `확인됨 / 확인 필요 / 학생이 추가함`으로 표시한다. 숫자 confidence는 학생 기본 화면에 노출하지 않는다.

### 학생 행동과 생각

- 원자 표시를 하나씩 눌러 H/C/N/O/F/Cl 중 알맞은 원소로 바꾼다.
- 놓친 원자는 사진을 눌러 추가하고, 원자가 아닌 표시는 삭제한다.
- 생각할 질문: `구의 색과 위치를 실제 모형과 하나씩 비교했는가?`

### 수정 지점과 오류 후 행동

- 낮은 신뢰도, 서로 겹친 후보, 화면 가장자리 후보는 자동 확정하지 않고 `확인 필요`로 남긴다.
- 원자가 가렸다면 `가려짐/미확인` 상태를 유지한다. 보이는 원자를 먼저 표시할 수는 있지만 `사진 다시 찍기` 또는 모형을 직접 대조한 명시적 확인 전에는 다음 단계로 진행하지 못한다.
- 후보가 0개여도 빈 화면으로 막지 않고 사진 탭으로 직접 원자를 추가하게 한다.
- 사진을 교체하면 기존 후보를 버릴지 확인하고, 보존 불가능한 이유를 설명한다.

### 완료 신호

- 확인 필요 후보와 `가려짐/미확인` 상태가 모두 0개이고, 학생이 모형 전체의 원자 수를 직접 대조한 뒤 `원자 확인 완료`를 선택한다.

## 3단계 — 결합 확인과 Physical graph 확정

### 학생이 보는 것

- 제목: `3/6 결합 확인`
- 같은 Physical Model 사진 위 원자와 결합 후보
- 불확실한 결합은 점선과 `확인 필요` 배지로 표시
- 연결 상태: `원자 5개 · 결합 4개 · 하나의 구조로 연결됨`

### 학생 행동과 생각

- 실제 막대를 보며 결합 후보를 유지하거나 삭제한다.
- 빠진 결합은 두 원자를 차례로 선택해 추가한다.
- 활동에서 필요한 경우에만 단일/이중/삼중 결합을 수정한다.
- 생각할 질문: `사진에서 막대로 직접 연결된 원자끼리만 이어졌는가?`

### 수정 지점과 오류 후 행동

- 단일 분자 활동에서 조각이 나뉘면 다음 문구와 함께 검증 단계 진입을 막는다.
  - `현재 구조가 여러 조각으로 나뉘어 있습니다. 하나의 분자를 만들려면 원자 사이를 결합으로 연결해 주세요.`
- 보이지 않는 막대를 AI가 추측해 채우지 않는다. `확인 필요`, `사진 다시 찍기`, `교사에게 확인` 중 다음 행동을 제시한다.
- 원자 종류 오류를 발견하면 2단계로 돌아가 수정할 수 있다. 이때 이후 결과는 아직 없으므로 손실 없이 다시 확인한다.

### 완료 신호

- 모든 결합 후보가 확인됐고 활동의 연결 정책을 만족한 뒤 학생이 `이 연결 구조로 확인하기`를 선택한다.
- 이 시점의 산출물은 **학생이 확인한 Physical Model graph**이며 아직 분자 정체나 Reference가 아니다.

## 4단계 — 구조 검증과 분자 확인

### Physical / Reference의 첫 명시적 분리

이 단계에서 두 영역을 처음 동시에 보여 준다.

- 왼쪽/상단: `내가 확인한 모형 · Physical Model` — 학생이 확정한 원자와 결합
- 오른쪽/하단: `과학적 Reference 준비` — 검증 전에는 잠금 상태

Physical 화면은 1단계부터 출처 라벨을 유지한다. 이 단계에서는 Reference의 이름이나 3D 데이터를 아직 만들지 않고, `검증 후 별도로 제공`된다는 잠금 경계만 보여 준다. Scientific Reference의 실제 내용은 5단계에서 처음 나타난다.

### 학생이 보는 것

- 제목: `4/6 구조 확인`
- 먼저 연결성 검사를 보여 주고, 이후 화학 검증 상태를 쉬운 말로 표시
- 검증 성공 시 분자식, 분자 이름/후보, `구조 검증 완료` 배지
- SMILES, Molfile, RDKit 같은 기술 상세는 학생 기본 화면에서 숨기고 교사용/개발자 근거에만 둔다.

### 학생 행동과 생각

- 원자 수, 결합 수, 연결 조각 수가 자신이 만든 모형과 같은지 확인한다.
- 검증된 분자 후보가 자신의 제작 의도와 맞는지 확인한다.
- 생각할 질문: `내가 만든 원자와 결합만으로 이 분자식이 설명되는가?`

### 수정 지점과 오류 후 행동

- 원자가 문제면 `원자 수정`으로 2단계, 연결/결합차수가 문제면 `결합 수정`으로 3단계에 바로 돌아간다.
- 원자가나 결합수가 맞지 않으면 문제가 있는 원자/결합을 강조하고 학생이 할 수 있는 한 가지 다음 행동을 제시한다.
- 가능한 정체가 여러 개면 하나를 자동 확정하지 않는다. 일치 근거를 비교하거나 구조를 다시 확인하게 한다.
- 정체를 찾지 못해도 `모르는 구조`로 명확히 표시하고 허위 이름을 만들지 않는다.
- 이전 단계 변경 시 분자식, 정체, Reference 후보를 즉시 무효화한다.

### 완료 신호

- 검증이 통과하고 학생이 `Reference 3D에서 확인하기`를 선택한다.

## 5단계 — Scientific Reference 3D 탐색

### 학생이 보는 것

- 제목: `5/6 과학적 Reference 3D`
- 큰 3D 캔버스와 `Scientific Reference` 출처 배지
- 출처, 좌표 유형/생성 방법, 현재 구조와의 일치 검증 상태
- 회전, 확대·축소, 초기 방향, 전체 보기
- 보기 모드: `구조`, `거리`, `각도`. 일반 PubChem 3D 입력은 기본적으로 시각화 전용이다. N5 Scanner의 고정 identity→CID 목록처럼 CID·계산 conformer 방법·Å/도 단위·SDF 결합 선택 규칙을 코드와 정책에 명시한 allowlist만 거리·각도를 활성화한다.

### 학생 행동과 생각

- 손가락/마우스로 회전하고 확대하여 원자가 같은 평면에 있는지, 입체적으로 벌어졌는지 관찰한다.
- 거리에서는 실제 graph로 결합된 원자 2개만 선택한다.
- 각도에서는 중심 원자와 그에 결합된 두 이웃 원자만 선택한다.
- 생각할 질문: `2D 연결 관계와 3D 공간 배치는 무엇이 같고 무엇이 다른가?`

### 수정 지점과 오류 후 행동

- 외부 3D 자료를 찾지 못하거나 네트워크가 실패하면 4단계 검증 결과를 유지한다. `다시 시도`, `3D 없이 비교 준비`, `교사에게 확인`을 제공한다.
- 후보가 여러 개면 학생이 구조 일치 근거를 보고 선택한 뒤 다시 검증한다. 자동으로 첫 후보를 사용하지 않는다.
- 거리·각도는 별도 측정 정책이 승인한 3D 좌표 출처 또는 명시된 계산 방법에서만 표시하고 `Reference 좌표에서 계산한 값`이라고 쓴다. 출처 라벨이 존재하거나 구조 일치 검증을 통과했다는 사실만으로 측정을 허용하지 않으며, 실험값이라고 부르지 않는다.
- VSEPR은 선택한 중심 원자 주변의 이상적 모형으로 별도 표시하며 Scientific Reference 전체 구조와 합치지 않는다.

### 완료 신호

- 학생이 구조를 한 번 이상 회전하고, 수업에서 요구한 관찰 또는 허용된 측정을 완료한 뒤 `내 모형과 비교하기`를 선택한다.

## 6단계 — Physical Model ↔ Scientific Reference 비교와 설명 수정

### 학생이 보는 것

- 제목: `6/6 구조 비교`
- 데스크톱: 두 영역을 같은 크기로 나란히 표시
- 모바일: 큰 화면 하나와 `내가 만든 모형 / 과학적 Reference` 전환 버튼. 현재 출처 라벨은 항상 유지
- Physical 쪽에는 사진과 확인한 graph, Reference 쪽에는 검증된 3D와 출처 표시
- 비교 기록: `같은 점`, `다른 점`, `내 설명을 어떻게 바꿀까?`

### 학생 행동과 생각

- 원자 수와 연결 관계가 같은지 먼저 확인한 뒤 상대적 공간 배치와 각도를 비교한다.
- 사진의 픽셀 거리와 Reference의 Å 값은 직접 비교하지 않는다.
- Structure Coach의 관찰 질문에 따라 차이를 찾고 처음 설명을 수정한다.
- 대표 질문:
  - CH4: `중심 탄소 주위 네 결합 방향이 서로 가능한 한 멀리 떨어져 있는지 살펴보세요.`
  - NH3: `질소 주위 결합 방향과 보이지 않는 비공유 전자쌍이 모양에 어떤 영향을 주는지 생각해 보세요.`
  - H2O: `사진에서 원자가 가려졌더라도 확인한 연결 관계와 굽은형 공간 배치가 어떻게 다른 정보인지 비교해 보세요.`

### 수정 지점과 오류 후 행동

- `다시 만들기`, `사진 다시 찍기`, `원자·결합 다시 확인`, `설명 수정`으로 돌아갈 수 있다.
- Physical과 Reference의 차이를 곧바로 `틀림`으로 단정하지 않고 모형 키트의 제약, 사진 시점, 이상 모형/좌표 출처를 구분한다.
- Reference가 없으면 비교 완료로 위장하지 않는다. Physical 관찰 기록은 저장할 수 있지만 `Reference 비교 미완료`를 표시한다.

### 완료 신호

- 학생이 관찰한 차이 하나와 그 이유에 대한 수정 설명 하나를 기록한다.
- 마지막 행동은 `정답 보기`가 아니라 `다시 비교`, `다시 만들기`, `설명 저장`이다.

## 오류와 불확실성의 공통 복구 규칙

| 상황 | 학생에게 보이는 상태 | 다음 행동 |
|---|---|---|
| 사진이 흐리거나 가림 | `사진에서 일부 원자를 확인하기 어렵습니다.` | 다시 촬영 / 다른 사진 / 직접 표시 |
| 원자 후보가 없음 | `자동으로 찾지 못했습니다. 직접 원자를 표시할 수 있습니다.` | 사진을 눌러 원자 추가 |
| 원자 후보가 모호함 | `확인 필요`와 후보 위치 | 원소 선택 / 삭제 / 재촬영 |
| 결합이 보이지 않음 | 점선 `확인 필요` | 추가·삭제 / 재촬영 / 교사 확인 |
| 구조가 여러 조각 | 연결 조각 수와 수정 안내 | 빠진 결합 연결 / 원자 삭제 |
| 화학 검증 실패 | 문제 지점과 학생용 한 문장 | 원자 수정 또는 결합 수정으로 이동 |
| 정체 후보가 여러 개 | 후보 수와 일치 근거 | 구조 재확인 / 후보 직접 검토 |
| 3D 자료 없음·네트워크 실패 | `2D 구조 확인 결과는 유지됩니다.` | 재시도 / 3D 없이 관찰 기록 |
| 허용된 측정 출처 없음 | 거리·각도 비활성화와 이유. allowlist 밖 PubChem 3D는 시각화 전용 | 구조 관찰 계속 / 교사 확인 |

## 기술적으로 꼭 필요한 기능

1. 모바일 사진 촬영/선택, 미리보기, 교체·삭제와 세션 내 출처 관리
2. 원자 후보 overlay, `확인 필요` 상태, 직접 추가·원소 변경·삭제, N2~N6까지 유지되는 stable atom ID·원본 이미지 좌표·후보 근거
3. stable atom ID를 참조하는 결합 후보, stable bond ID, 추가·삭제·필요한 결합차수 수정, editable Physical graph
4. 단계별 확정 상태, Physical graph revision, 상위 입력 변경 시 해당 revision의 검증·identity·3D·measurement 무효화
5. graph 연결성 검사와 기존 RDKit validation adapter 연결
6. 검증된 identity/Reference 후보와 Physical state의 분리된 데이터 계약
7. 출처가 표시된 기존 3D viewer, 기본 차단 방식의 측정 출처/방법 승인 목록, graph 인접성 기반 원자 선택·측정 제한
8. Physical/Reference 비교 화면과 학생 관찰·수정 설명 입력
9. 키보드/터치 접근, 44px 이상 주요 조작, 색 외에도 기호·문구로 상태 구분
10. 개발자 오류 대신 학생 행동을 안내하고, 기술 로그는 교사용/개발자 영역에 유지

## 단계 사이에서 보존할 최소 데이터 불변조건

- Physical 상태는 원본 사진, stable atom/bond ID, 이미지 좌표, 후보 근거, 학생 확인 상태, graph revision을 가진다. Reference 좌표나 Å 측정값을 넣지 않는다.
- N3~N6은 같은 atom ID를 사용해 학생이 수정한 원자와 결합을 추적한다. 삭제·재추가로 ID나 graph revision이 바뀌면 이전 파생 결과를 재사용하지 않는다.
- Reference 상태는 검증한 Physical graph revision, 구조 일치 상태, 좌표 출처·방법, `시각화 전용 / 좌표 계산 측정 허용 / 검토된 실험값` 구분을 가진다.
- 측정 허용의 기본값은 `차단`이다. 일반 PubChem 3D는 `시각화 전용`이며, Scanner N5처럼 고정 CID·계산 방법·단위·SDF 결합 선택 규칙이 승인 목록에 모두 명시된 경우에만 거리·각도를 연다.
- Scanner shell은 독립적으로 상태를 소유하고 기존 simple 기본 진입, legacy 흐름, `App.tsx` 상태의 의미를 변경하지 않는다.

## 초기 MVP에 불필요한 기능

- 범용 Vision 모델 또는 자체 모델 학습
- 사진 한 장에서 완전한 3D 좌표 복원
- 여러 사진의 3D 재구성, AR/VR, 실시간 카메라 추적

- AI 챗봇이나 장문의 자동 해설
- 전체 주기율표, 모든 분자, 자동 IUPAC 이름 생성
- 사진 픽셀/키트 막대에서 Å 결합길이 계산
- 불확실한 후보의 자동 확정

## N2~N6이 필요한 이유

| 노드 | 담당 학생 경험 | 없을 때 끊기는 지점 |
|---|---|---|
| N2 — Image → Atom Candidates | 1~2단계 사진 입력, 원자 후보, 수동 확인·수정 | 학생의 실물 제작물이 디지털 구조로 진입하지 못한다. |
| N3 — Bond Confirmation → Molecular Graph | 3단계 결합 확인과 Physical graph 확정 | 원자 목록이 화학적으로 검증 가능한 연결 구조가 되지 못한다. |
| N4 — Chemistry Validation → Molecule Identity | 4단계 연결성·화학 검증과 정체 확인 | 추정 graph가 사실처럼 Reference 단계로 넘어갈 수 있다. |
| N5 — Scientific Reference 3D + Measurement | 5단계 출처가 있는 3D 탐색과 허용된 측정 | 학생이 자신의 모형을 비교할 과학적 대상을 얻지 못한다. |
| N6 — Physical vs Reference + Structure Coach | 6단계 차이 관찰, 설명 수정, 다시 만들기 | 기능은 존재해도 핵심 학습인 비교·성찰이 완성되지 않는다. |

## 학생 화면과 교사용 기술 근거의 경계

- 학생 화면: `연결됨`, `확인 필요`, `구조 검증 완료`, `Reference 좌표에서 계산한 값`처럼 행동과 의미를 먼저 표시한다.
- 교사용/개발자 근거: SMILES, Molfile, RDKit 로그, 후보 confidence 원값, PubChem CID, 좌표 형식과 상세 source note를 제공한다.
- 학생에게 `RDKit.js 검증 실패`, `canonical mismatch` 같은 원문 오류를 직접 보여 주지 않는다.

## 대표 오개념 방지와 P0 자동 탈락 조건

- CH4의 원자·결합 graph가 맞아도 실물 모형의 공간 배치가 평면에 가까울 수 있다. 이를 4단계 화학 검증 실패로 처리하지 않고 6단계 공간 구조 비교에서 다룬다.
- NH3/H2O 사진에서 가려진 원자를 `없음`으로 확정하지 않는다. 비공유 전자쌍을 사진 속 실물 원자처럼 인식하지도 않는다.
- H/F/Cl 1, O 2, N 3, C 4의 결합 확인은 초기 중성 폐각 분자 활동의 제한된 기준이며 모든 화학종의 보편 법칙으로 설명하지 않는다.
- 다음 중 하나라도 발생하면 해당 설계/구현은 자동 탈락이다.
  - 학생이 확정하지 않은 후보가 identity나 Reference로 넘어간다.
  - Physical 사진·막대의 거리를 Å로 표시하거나 Reference 측정과 합친다.
  - 분리 graph, 검증 실패, 지원 밖 구조에 분자명·계산값·Reference를 사실처럼 표시한다.
  - 원자/결합 수정 뒤 이전 formula, identity, 3D, measurement가 남아 있다.
  - Reference에 좌표 출처·방법·구조 일치 상태가 없다.
  - 시각화 전용 PubChem 3D 또는 CID·계산 방법·단위·결합 선택 규칙 승인 없이 출처 라벨만 있는 좌표에서 거리·각도를 활성화한다.
  - 단일 사진에서 완전한 3D, 공면성, 가려진 원자의 부재를 확정한다.
  - fixture/mock 또는 실패한 인식을 실제 분석 성공처럼 보이게 한다.
